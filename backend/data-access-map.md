## Notes for the server

- `audit`: Append-only schema; insert-only grant; nightly signed digest to write-once storage
- `btg`: Server-issued, time-boxed grant; review queue
- `users`: Owned by the identity provider (SCIM); app keeps roles and scope only
- `patients`: Direct identifiers field-encrypted (envelope keys); keyed-hash search index
- Every PHI endpoint: authenticate (OIDC session), authorise (role + care relationship, deny by default), then write the audit row in the same transaction.
- `boot` reads come from `GET /api/bootstrap`, which returns only the signed-in user's permitted slice.
